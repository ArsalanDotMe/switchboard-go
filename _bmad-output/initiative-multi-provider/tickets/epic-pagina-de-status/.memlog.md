- (requirement) R1 (parent R12): GET /status devolve página HTML renderizada no servidor com nome (ou posição), estado, cooldown e uso (rolling, weekly, monthly) de cada chave, sem exigir autenticação
- (requirement) R2 (parent R12): a página não expõe valor de chave nem cria endpoint JSON novo; /admin/* segue exigindo PROXY_API_KEY
- (requirement) R3 (parent R12): erro na consulta de uso de uma chave aparece na linha dela e não derruba a página
- (requirement) R4 (parent R12): a página funciona no binário e na imagem Docker sem arquivo externo
- (decision) Eduardo (2026-10-29): página renderizada no servidor, sem API exposta; substitui a proposta de abrir GET /admin/keys e servir HTML estático com JS
- (assumption) o cache de uso existente (usageCache) basta para limitar consultas ao upstream de uma página aberta; sem limitação de taxa
- (decision) Eduardo aceitou o risco de UsageCacheTTL=0 na página aberta (sem piso de TTL); stories 1 (tracer) e 2 planejadas
